## Aufgabe 1
:::::aufgabe[Schritt 1]
<Answer type="state" id="d25f0cbd-d494-4766-bd55-c2c83b6e4b93" />

Erstellen Sie ein Programm, welches für eine gegebene Zahl `Z` prüft, ob diese durch die Zahlen 1, 2, 3, 4, ... (bis zur gegebenen Zahl `Z`) teilbar ist. Dabei soll ein `!` ausgegeben werden, wenn die Zahl teilbar ist, und ein `.` wenn sie nicht teilbar ist. Die Ausgabe soll in einer Zeile erfolgen.

::::info[Beispiele]
:::flex
```
(7)     ! . . . . . !
```
> `7` ist durch 1 und 7 teilbar.
::br
```
(10)    ! ! . . ! . . . . !
```
> `10` ist durch 1, 2, 5 und 10 teilbar.
::br
```
(15)    ! . ! . ! . . . . . . . . . !
```
> `15` ist durch 1, 3, 5 und 15 teilbar.
:::
::::

```py live_py id=06c789a6-ccd8-45d5-8254-c87b41ec7d2a
Z = 7

```

:::tip
Verändern Sie den Initialisierungswert der Variable `Z`, um das Programm mit anderen Zahlen zu testen.
:::

<Solution id="dcc8b9cd-4542-47ed-87c0-6916f6df3a0a">
```py live_py slim
Z = 10
for i in range(1, Z + 1):
    if Z % i == 0:
        print('!', end=' ')
    else:
        print('.', end=' ')
```
</Solution>

## Aufgabe 5
:::::aufgabe[Schritt 1]
<Answer type="state" id="6446018c-f8e8-4c89-9d77-cdf759c55018" />

Ihr Taschenrechner hat einen Wackelkontakt: Er kennt zwar noch die vier Grundrechenarten `+`, `-`, `*`, `/`, aber die Kabel sind vertauscht worden. Wenn man ihn benutzt, rechnet er nicht das, was man eingibt, sondern etwas anderes — aber immer auf die gleiche (falsche) Art.

Erstellen Sie ein Programm, welches von der Benutzer:in zwei ganze Zahlen `a` und `b` sowie einen Operator (`+`, `-`, `*` oder `/`) einliest und je nach eingegebenem Operator folgendes berechnet und ausgibt:

| Eingabe | Der Taschenrechner berechnet stattdessen |
|---------|------------------------------------------|
| `+`     | Subtraktion                              |
| `-`     | Multiplikation                           |
| `*`     | Ganzzahl-Teil der Division mit Rest      |
| `/`     | Restwert-Teil der Division mit Rest      |

::::info[Beispiele]
:::flex
```
> a eingeben: 7
> b eingeben: 3
> Operator eingeben: +
> Resultat: 4
```
::br
```
> a eingeben: 5
> b eingeben: 5
> Operator eingeben: -
> Resultat: 25
```
:::
::::

```py live_py id=9b8b97fc-bc75-4ff9-a47c-e3e13e25c624
```

<Solution id="c13a96ca-601e-4309-bae8-f489d8d01cd1">
```py live_py slim
a = int(input('a eingeben: '))
b = int(input('b eingeben: '))
op = input('Operator eingeben: ')
if op == '+':
    print(f'Resultat: {a - b}')
elif op == '-':
    print(f'Resultat: {a * b}')
elif op == '*':
    print(f'Resultat: {a // b}')
elif op == '/':
    print(f'Resultat: {a % b}')
```
</Solution>

Erweitern Sie Ihr Programm aus dem vorherigen Schritt nun so, dass bei einer Eingabe eines unbekannten Operators eine entsprechende Fehlermeldung erscheint und der User / die Userin den Operator nochmal neu eingeben muss – und zwar so lange, bis es ein gültiger Operator ist.

```
> Operator eingeben: -
> Resultat: 21
```
:::

:::tip[Darstellung]
Bei diesem Code-Editor erscheint für die Eingabe ein Eingabefeld anstelle eines Pop-Ups. Zudem ist es normal, dass die Eingaben nach dem Drücken der [[Enter]]-Taste direkt wieder verschwinden.

<Solution id="4d2e964f-46f0-4119-aca0-251851ef3a2c">
```py live_pyo
a = int(input('a eingeben: '))
b = int(input('b eingeben: '))
op = input('Operator eingeben: ')
ok = False
while not ok:
    if op == '+':
        print(f'Resultat: {a - b}')
        ok = True
    elif op == '-':
        print(f'Resultat: {a * b}')
        ok = True
    elif op == '*':
        print(f'Resultat: {a // b}')
        ok = True
    elif op == '/':
        print(f'Resultat: {a % b}')
        ok = True
    else:
        print(f'{op} ist kein gültiger Operator.')
        op = input('Operator eingeben: ')
```
